# n8n on Render (Blueprint)

Minimal [Render Blueprint](https://render.com/docs/infrastructure-as-code) repo to run [n8n](https://n8n.io/) as a **Docker image web service** — no custom app server, no Dockerfile.

Uses the official image: `docker.io/n8nio/n8n:latest` on port **5678**, with HTTP basic auth and secrets generated by Render.

## Free tier / demo notice

This setup targets **portfolio or demo** use on Render’s **free** web service plan:

- **Sleep on inactivity** — Free web services spin down after ~15 minutes without traffic. The first request after sleep can take 30–60+ seconds while the instance wakes up.
- **Ephemeral filesystem** — Workflow data is stored locally in the container. Redeploys and restarts can **lose workflows** unless you add Postgres or a persistent disk (not included here to keep the blueprint simple).
- **Not for production** — For real workloads, use a paid instance, persistent storage (Postgres or disk), and review [Render’s n8n guide](https://render.com/docs/deploy-n8n).

## What gets deployed

| Resource | Details |
|----------|---------|
| Web service `n8n` | `runtime: image`, `plan: free`, `docker.io/n8nio/n8n:latest` |
| Port | `5678` (`PORT` + `N8N_PORT`) |
| Auth | Basic auth user `admin`; password generated by Render |
| URL config | `N8N_HOST` and `WEBHOOK_URL` from the service’s Render URL via `fromService` (no hardcoded hostname) |

After deploy, open the service URL from the Render dashboard. Log in with:

- **User:** `admin`
- **Password:** Render → **n8n** service → **Environment** → `N8N_BASIC_AUTH_PASSWORD`

Save `N8N_ENCRYPTION_KEY` from the same page — if you change it later, encrypted credentials in n8n break.

## Deploy with Blueprint

### 1. Push this repo to GitHub

Create a new empty repository on GitHub (e.g. `your-username/n8n-render`), then push this folder (see git commands at the end of this README).

### 2. Connect Render

1. Sign up or log in at [render.com](https://render.com).
2. **New** → **Blueprint**.
3. Connect GitHub and select this repository.
4. Confirm branch (usually `main`) and Blueprint name.
5. Click **Deploy Blueprint**.

Render creates the `n8n` web service, generates `N8N_ENCRYPTION_KEY` and `N8N_BASIC_AUTH_PASSWORD`, and wires `N8N_HOST` / `WEBHOOK_URL` from the live service URL.

### 3. Verify

1. Wait until the deploy shows **Live**.
2. Open `https://<your-service>.onrender.com` (shown on the service page).
3. Sign in with basic auth (`admin` + generated password).
4. If you use **Webhook** nodes, confirm the test URL uses your `onrender.com` host (from `WEBHOOK_URL`). If webhooks misbehave, set `WEBHOOK_URL` manually to `https://<your-host>/` (with trailing slash) under **Environment** and redeploy.

## Environment variables (reference)

Defined in `render.yaml`:

| Variable | Source |
|----------|--------|
| `N8N_PROTOCOL` | `https` |
| `N8N_PORT` | `5678` |
| `GENERIC_TIMEZONE` | `America/New_York` |
| `N8N_ENCRYPTION_KEY` | Generated by Render |
| `N8N_BASIC_AUTH_ACTIVE` | `true` |
| `N8N_BASIC_AUTH_USER` | `admin` |
| `N8N_BASIC_AUTH_PASSWORD` | Generated by Render |
| `N8N_HOST` | `fromService` → `property: host` |
| `WEBHOOK_URL` | `fromService` → `RENDER_EXTERNAL_URL` |
| `PORT` | `5678` (Render routing hint) |

## Pin n8n version (optional)

Replace `latest` in `render.yaml`:

```yaml
image:
  url: docker.io/n8nio/n8n:1.83.2
```

Push to trigger a new Blueprint sync.
